**OneGuest Studio** is a Next.js and LiveKit prototype for remote recording and 1-on-1 interviews. It captures host and guest media in separate browser recordings, provides a guest invitation flow, a studio teleprompter, and basic transcript editing utilities. It does not include AI features.

Host studio management uses Google OAuth. Guest joining does not require an account. Media and interview metadata still use local filesystem storage, and no RTMP relay is configured.

---

## Key Features

### 1. Studio Workspace & Navigation
- **Dashboard**: High-level studio overview, quick-launch studio card, quick guest link parser, recent interview cards with video thumbnail headers, and dual Host/Guest avatar badges.
- **Interviews**: Complete interview manager with search, filter tabs (*All*, *Scheduled*, *Active*, *Completed*), unique guest invitation links, private passcode support, and one-click studio entry.
- **Recordings Library**: Participant track cards, raw audio/video preview, individual downloads, and batch download controls.
- **Settings**: Local audio/video hardware test suite and recording configuration information.

### 2. Separate Participant Recordings
- The host browser records the host's own camera and microphone; the guest browser records the guest's own camera and microphone.
- The host coordinates guest start/stop through LiveKit data messages. A combined preview recording may also be generated by the host browser.
- Browser `MediaRecorder` output is encoded media, not uncompressed source. Capture formats and quality depend on browser support and device settings.
- Recordings are uploaded after they are finalized. If a participant closes the tab or the browser fails before upload, that participant's in-memory recording can be lost.
- The preflight UI warns about missing participant tracks. Automated tests currently verify helpers and storage metadata; they do not simulate two real browsers or validate the media content of recorded files.

### 3. In-Studio Teleprompter & Notes Overlay
- **Floating Script Drawer**: Auto-scrolling teleprompter embedded directly in the studio stage.
- **Customizable Pace**: Play/Pause controls with variable scrolling speed (`1x` to `5x`) and adjustable font sizes (`14px` to `24px`).
- **Auto-Persistence**: Script and interview talking points automatically sync to browser `localStorage` per room ID.

### 4. Guest Joining & Green Room
- **Direct Link Onboarding (`/join/<invite-token>`)**: Guests join using a cryptographically random invitation link with zero account creation or payment barriers. Links expire after 30 days and may also require the studio passcode.
- **Host Authentication**: The configured, verified Google host account is required for the dashboard, studios, editor, and recordings. Guest invitation routes do not require authentication.
- **Green Room Pre-Flight**: Live camera preview, real-time Web Audio API VU meter, device selectors with test sound chimes, and headphone advisory.
- **Server-Side Token Minting**: LiveKit tokens are minted by the server; LiveKit API secrets are not included in client links.

### Not yet production-ready
- **Persistence**: Interviews are stored in `data/interviews.json` and recordings in `data/recordings` (or `RECORDINGS_STORAGE_PATH`). These are local filesystem stores. The included Render Blueprint uses the free plan and does not configure a persistent disk, so files can be lost on redeploy/restart.
- **Access control**: The allowlisted Google host account protects studio management, recordings, and host-only APIs. Guests use opaque, 30-day invitation links and can be asked for a separate room passcode. This prototype has not had a production security assessment.
- **Live streaming**: No LiveKit Egress or RTMP relay is configured. The studio now reports this as unavailable and does not simulate a live stream.
- **Transcription and highlights**: No speech-to-text service is configured. Transcript highlights are unavailable, and an empty transcript is shown rather than fabricated sample dialogue.
- **Exports**: The editor does not currently have a backend rendering pipeline for final video exports. Downloading an original track is not the same as rendering an edited or cropped video.

## Tech Stack & Architecture

- **Framework**: Next.js 16.4.2 (App Router with Turbopack)
- **UI Library**: React 19.3.1
- **Styling**: Tailwind CSS v4 & Lucide React Icons
- **Real-Time WebRTC**: `@livekit/components-react` (2.9.24) & `livekit-client` (2.23.0)
- **Server Token SDK**: `livekit-server-sdk` (2.19.1)
- **Video Processing**: Custom WebGL Shader Pipeline implementing `TrackProcessor`
- **Testing**: Native Node.js test runner (`node --test`)
- **Deployment Platform**: Render (Web Service via `render.yaml`)

## Getting Started

### 1. Prerequisites
- Node.js `>= 20.9.0` (Node 22 LTS recommended)
- A free [LiveKit Cloud Account](https://cloud.livekit.io) (or self-hosted LiveKit server)

### 2. Clone and Install Dependencies
```bash
git clone https://github.com/SelvaJeyaKrishnan/VC.git
cd VC
npm install
```

### 3. Configure Environment Variables
Create a `.env.local` file in the root directory:
```env
# LiveKit Cloud Credentials (from https://cloud.livekit.io)
LIVEKIT_URL=wss://your-project.livekit.cloud
LIVEKIT_API_KEY=your_api_key
LIVEKIT_API_SECRET=your_api_secret

# Google OAuth Web application credentials from Google Cloud
GOOGLE_CLIENT_ID=your_google_client_id
GOOGLE_CLIENT_SECRET=your_google_client_secret
NEXTAUTH_URL=http://localhost:3000
NEXTAUTH_SECRET=generate_a_long_random_secret
AUTHORIZED_HOST_EMAIL=selva72007@gmail.com

# Optional Base URL for absolute guest invite links
NEXT_PUBLIC_APP_URL=http://localhost:3000
```

If `.env.local` already exists, preserve its LiveKit settings and add the local authentication settings above. This file is ignored by Git. Use the local OAuth client credentials and a fresh local session secret; do not copy a secret that has been shared publicly.

Create a Google OAuth client with application type **Web application**. Add `http://localhost:3000` as an authorized JavaScript origin and `http://localhost:3000/api/auth/callback/google` as an authorized redirect URI for local development. `AUTHORIZED_HOST_EMAIL` is the one exact Google account permitted to sign in; the account must have a verified email. Generate `NEXTAUTH_SECRET` with a cryptographically secure random value, such as `openssl rand -base64 32`. Keep the client secret and session secret server-side; never put them in `NEXT_PUBLIC_*` variables or source control.

Legacy interviews created before ownership was added have no owner recorded. They remain inaccessible until `LEGACY_DATA_OWNER_EMAIL` is set to the exact Google account email that should own those records. This assigns all ownerless legacy interviews to that account; omit the variable if that is not appropriate.

### 4. Run Development Server
```bash
npm run dev
```
Open [http://localhost:3000](http://localhost:3000) in your browser.

## Testing & Quality Assurance

Run the automated test suite:
```bash
# Run all 35 unit and E2E simulation tests
npm test

# Run TypeScript type-checking
npm run lint

# Build production bundle
npm run build
```

The test suite covers:
- **`tests/recordingEndToEnd.test.mjs`**: End-to-end multi-participant studio recording simulation, 4-stem isolation verification, and missing guest safety pre-flight check.
- **`tests/recordingEngine.test.mjs`**: Codec negotiation (WebM VP9/Opus & MP4), track readiness validator, and participant search logic.
- **`tests/recordingStore.test.mjs`**: Multi-track persistence, manifest generation, 4-stem physical verification, and path traversal security.
- **`tests/guestFlow.test.mjs`**: URL/code parser for guest links and credential leakage prevention.
- **`tests/tokenService.test.mjs`**: Token validation, placeholder credential detection, and JWT grant signing.
- **`tests/selfieEnhancer.test.mjs`**: YCbCr skin tone detection math and shadow lift tone curve.
- **`tests/interviewStore.test.mjs`**: Session CRUD, room lookup, and passcode validation.
- **`tests/health.test.mjs`**: Render deployment monitoring endpoint schema and status.
- **`tests/utils.test.mjs`**: ID generators, guest codes, initials, and Tailwind merging.

## Deploying to Render

This repository includes a [`render.yaml`](render.yaml) Blueprint configuration for a Render Web Service. It is suitable for evaluation, not durable production recording storage.

### Quick Setup:
1. Log in to [Render Dashboard](https://dashboard.render.com).
2. Click **New +** → **Web Service** (or **Blueprint** to load `render.yaml`).
3. Select your GitHub repository: `SelvaJeyaKrishnan/VC`.
4. Configure the environment variables in Render:
   - `LIVEKIT_URL`: `wss://<your-project>.livekit.cloud`
   - `LIVEKIT_API_KEY`: `<your_livekit_api_key>`
   - `LIVEKIT_API_SECRET`: `<your_livekit_api_secret>`
   - `NODE_VERSION`: `22.14.0`
5. In **Render Dashboard → your Web Service → Environment**, set:
   - `GOOGLE_CLIENT_ID`: the OAuth client ID for a Google **Web application**.
   - `GOOGLE_CLIENT_SECRET`: the secret paired with that client ID.
   - `AUTHORIZED_HOST_EMAIL`: the exact, verified Google account email allowed to manage this installation.
   - `NEXTAUTH_SECRET`: a newly generated, high-entropy secret (for example, `openssl rand -base64 32`).
   - `NEXTAUTH_URL`: `https://vc-vu80.onrender.com` (no callback path or trailing slash).
   - `NEXT_PUBLIC_APP_URL`: `https://vc-vu80.onrender.com`, used to generate shareable invitation URLs.
   - `LIVEKIT_URL`, `LIVEKIT_API_KEY`, and `LIVEKIT_API_SECRET`: the matching server-side LiveKit project credentials.
   - `LEGACY_DATA_OWNER_EMAIL` only if ownerless legacy studios should be assigned to the authorized host; leave it unset otherwise.
6. In **Google Cloud Console → APIs & Services → Credentials → your OAuth 2.0 Web client**, register this exact **Authorized redirect URI**: `https://vc-vu80.onrender.com/api/auth/callback/google`. For a custom domain, register that domain's corresponding `/api/auth/callback/google` URI too. The OAuth consent screen must allow the host account to authenticate.
7. Save the variables and deploy/redeploy the service. Never share OAuth secrets in chat or commit them to GitHub.

Render will install dependencies, build the app, verify `/api/health`, and launch the service. Authentication and owner-based authorization are implemented, but the included free service does not configure a persistent disk or cloud media store; recordings and interview metadata can be lost on redeploy or restart. Do not store irreplaceable recordings until durable storage is configured and tested.
